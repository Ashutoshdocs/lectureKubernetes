==============================================================
PART 1 - UNDERSTAND THE DEMO
==============================================================

We start with:

    CPU request    = 50m
    Memory request = 32Mi

The application intentionally consumes CPU.

VPA observes actual resource usage.

VPA then calculates:

    Target
    Lower Bound
    Upper Bound

Example:

    Current:
        CPU request = 50m
        Memory      = 32Mi

    VPA recommendation:

        CPU    = 200m
        Memory = 64Mi

VPA can then recreate the Pod using the recommended
resource requests.


==============================================================
PART 2 - VPA ARCHITECTURE
==============================================================

                Metrics Server
                      |
                      v
                VPA Recommender
                      |
             Calculates recommendation
                      |
                      v
                 VPA Updater
                      |
             Decides whether Pod
                 needs update
                      |
                      v
             Admission Controller
                      |
             Injects recommended
             CPU / Memory values
                      |
                      v
                    Pod


Three VPA components:

1. Recommender
2. Updater
3. Admission Controller

==============================================================

VPA does NOT increase Pod count.

    Deployment
        |
        +---- Pod
              CPU    = 50m

              Memory = 64Mi

    1 Pod


This is VERTICAL scaling.

PART 10 - TURN VPA ON
==============================================================

Now replace OFF configuration with ON configuration.

First delete the OFF VPA:

    kubectl delete -f 02-vpa-off.yaml


Then apply ON configuration:

    kubectl apply -f 03-vpa-on.yaml

    updateMode: "Recreate"


Meaning:

    VPA can evict the existing Pod

    Deployment creates a replacement Pod

    VPA Admission Controller injects
    recommended CPU / Memory values

==============================================================
PART 14 - VPA RECOMMENDATION TERMS
==============================================================

TARGET

Preferred resource recommendation.

Example:

    CPU = 200m


LOWER BOUND

Lower recommended boundary.

Example:

    CPU = 100m


UPPER BOUND

Upper recommended boundary.

Example:

    CPU = 300m


Conceptually:

    Lower          Target          Upper
      |              |               |
      v              v               v

    100m           200m            300m
      |--------------|---------------|

==============================================================

Our configuration:

    minAllowed:

      cpu: 50m
      memory: 32Mi


    maxAllowed:

      cpu: 400m
      memory: 256Mi


Meaning:

VPA should not recommend below:

    CPU    = 50m
    Memory = 32Mi


VPA should not recommend above:

    CPU    = 400m
    Memory = 256Mi


==============================================================
PART 16 - HPA VS VPA
==============================================================

HPA:

    1 Pod
      |
      v
    3 Pods
      |
      v
    5 Pods


HPA = MORE PODS


VPA:

    1 Pod
      |
      v
    CPU request increases
    Memory request increases


VPA = BIGGER RESOURCE ALLOCATION


==============================================================
PART 17 - HPA VS VPA VS CLUSTER AUTOSCALER
==============================================================

HPA:

    Changes number of Pods

    2 Pods -> 5 Pods


VPA:

    Changes resources of Pods

    CPU: 100m -> 300m


Cluster Autoscaler:

    Changes number of Nodes

    1 Node -> 2 Nodes


Remember:

    HPA  = More Pods

    VPA  = Bigger Pods

    CA   = More Nodes


==============================================================
PART 18 - ONE NODE CLUSTER LIMITATION
==============================================================

We have only one node.

Suppose VPA recommends:

    CPU = 2 CPU
    Memory = 4Gi


But the node has only:

    500m CPU available


The new Pod may become:

    Pending


VPA DOES NOT create another node.

Cluster Autoscaler is responsible for node scaling.


==============================================================
PART 19 - IMPORTANT PRODUCTION WARNING
==============================================================

Recreate mode may restart Pods.

Therefore:

    VPA Recreate
          |
          v
    Pod eviction
          |
          v
    New Pod


Potential impact:

    Temporary downtime


For production applications:

    Use appropriate update mode

    Consider:

        InPlace
        InPlaceOrRecreate
        Recreate

depending on Kubernetes/VPA support and workload requirements.
